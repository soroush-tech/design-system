## soroush.design@0.1.0

The soroush.design family under one name: an app installs this package and writes
`soroush.design/react/...` for everything it uses
([#136](https://github.com/soroush-tech/design-system/issues/136)).

### What it offers

- **Every path of the React platform, under `/react`.** `soroush.design/react/Button` is
  `@soroush.design/react/Button`, `soroush.design/react/theme` is its theme, and
  `soroush.design/react/hooks/useDebounce` and `soroush.design/react/markdown/Editor` are its hooks
  and its markdown library. `soroush.design/react` is the platform's root. Each entry is a re-export
  of one line, with its types, so an app loads only what it imports.
- **One copy of everything.** The package imports the platform and never bundles it, and the platform
  does the same with its libraries, so an app has one theme and one set of styles, whichever of the
  three names its files import from.
- **Theme extension by any of the names.** An app adds colors, sizes and component variants with
  `declare module 'soroush.design/react/theme'`, with the platform's name or with a library's. All
  reach `useTheme`, `styled`, `createTheme` and the props of every component.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react-components/docs/theming.md)
- **Room for the other platforms.** React Native and Vue arrive as `soroush.design/react-native/...`
  and `soroush.design/vue/...`, without a change to the React entry points.
- **Generated entry points.** `pnpm gen:umbrellas` writes the sources and the export map from the
  platform umbrellas, with the same generator the React platform uses, and CI fails when they drift.

### Packaging

- Dependency: `@soroush.design/react`, installed once with this package.
- Peers: `react` and `react-dom` `^19.2.8`, both optional, so an app that uses another platform of
  the family is not asked for them.
- An app that writes `soroush.design/react/markdown` also installs `@soroush.design/react-markdown`,
  the optional peer of the React platform; without it, importing a `markdown` entry point fails with
  a module-not-found error that names it.
- ESM and CJS builds with declarations, and a subpath export for every entry point. There is no
  root entry point.
