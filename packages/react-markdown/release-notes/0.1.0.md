## @soroush.design/react-markdown@0.1.0

The markdown package of the soroush.design React design system: an editor, a live preview, a
toolbar, a code surface and a diagram viewer, all drawn with the theme of your app
([#134](https://github.com/soroush-tech/design-system/issues/134)). An app installs it next to
`@soroush.design/react` and writes `@soroush.design/react-markdown/Editor`.

### What it offers

- **`Preview`** renders a markdown string to themed components: tables, task lists,
  strikethrough, autolinks, syntax-highlighted code and diagrams. Every heading gets the id
  GitHub gives it, so a `#section` link lands on it.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react-markdown/src/Preview/README.md)
- **`Control`, `Toolbar` and `Editor`** are the parts of an editor, with no layout of their own.
  `Control` owns the value and the selection, `Toolbar` has the formatting buttons, the heading and
  code-language selects, a table picker and a diagram picker with starter templates, and `Editor` is
  the source field with Tab to indent and caret restore. The `Editor` also works alone, with
  `value` and `onChange`. `useMarkdownContext()` gives a part of your own the same value and
  actions.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react-markdown/README.md#editor)
- **`LiveEdit`** is a preview you write on directly: each top-level block is editable in place and
  writes its change back to the markdown source, while blocks you did not touch keep their exact
  text.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react-markdown/src/LiveEdit/README.md)
- **`CodeBlock`** is the code surface of `Preview`, usable alone, with a copy button. Its colors
  come from `theme.syntax`, and `syntaxDark` and `syntaxLight` are ready to use.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react-markdown/src/CodeBlock/README.md)
- **`Mermaid` and its diagram viewer** draw a fenced `mermaid` block as a diagram with zoom, pan and
  fullscreen. Its colors follow the theme, and `theme.mermaid` overrides any of them.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react-markdown/src/Mermaid/README.md)
- **Theme slots.** `MarkdownEditor`, `MarkdownLiveEdit`, `MarkdownPreview`, `MarkdownToolbar` and
  `CodeBlock` are slots of `theme.components`, typed once any entry of the package is imported -
  they join `ThemeComponents`, which an app checks its looks against with
  `satisfies ThemeComponents` - next to the `theme.syntax` and `theme.mermaid` keys.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react-markdown/README.md#customizing-the-look)
- **The heavy parts load when they are used.** The diagram library is imported inside an effect,
  never when the package is imported, so a bundler gives it a chunk of its own and it is fetched
  only when a diagram renders.
- **Server rendering.** No part reads a browser global when it is imported. On the server a diagram
  renders as its source in a code block, which is also what an invalid diagram shows, so the
  markup stays the same when the page hydrates.
- **TypeScript.** Every part and every prop is typed, and the package has 100% test coverage.

### Packaging

- Peers: `@soroush.design/react` `^0.1.0`, `react` and `react-dom` `^19.2.8`.
- Dependencies: `@soroush.design/core`, `@soroush.design/react-hooks`, the markdown parser and renderer, `rehype-highlight`,
  `rehype-slug`, `remark-gfm`, and the DOM-to-markdown tools that `LiveEdit` uses (`unified`,
  `rehype-parse`, `rehype-remark`, `remark-stringify`), and `mermaid`.
- ESM and CJS builds with declarations: one entry point for each of `Control`, `Toolbar`, `Editor`,
  `LiveEdit`, `Preview`, `CodeBlock` and `Mermaid`, and the root, which exports them all.
- An app that never imports this package installs none of these dependencies: it is not a
  dependency of `@soroush.design/react`.
