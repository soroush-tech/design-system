## @soroush.tech/styled-system@5.9.0

Named breakpoints work everywhere and a breakpoint can be any media query, so a theme can carry
the breakpoints an app lays out from. Plain-length breakpoints produce exactly the CSS they did.
([#344](https://github.com/soroush-tech/core/issues/344))

### Added

- **Named breakpoints for array props** - `p={[1, 2, 3]}` maps onto `theme.breakpoints` in
  declared order when it is an object such as `{ tablet: '37.5em', web: '75em' }`. It threw
  before. The same holds in `css()`.
- **Media conditions as breakpoint values** - a condition or range such as
  `(600px <= width < 1200px)` or `(orientation: landscape)` becomes `@media <condition>`; a value
  starting with `@media` is used as written. A number gets `px`. A length keeps
  `@media screen and (min-width: <length>)`, byte for byte.
- **`createMediaQuery`**, **`breakpointQueries`** and the **`Breakpoints`** type - the helper the
  parsers use, exported for components that write their own media blocks.
  [docs](https://github.com/soroush-tech/core/blob/main/packages/styled-system/docs/breakpoints.md)
- **`_` in `ResponsiveValue`** - the base value of the object syntax, `{ _: 1, web: 2 }`, is typed.

### Fixed

- Object-syntax media blocks are written in breakpoint order. They were sorted by the text of the
  query, which put `100em` after `75em` only by luck and misordered conditions.
- A parser follows the theme's breakpoints: switching to a theme with other breakpoints writes
  their queries. It kept the first theme's before.

### Upgrade

- From 5.8.x: drop-in. Styles from the object syntax keep their values; only the order of
  their keys follows the breakpoints now.
