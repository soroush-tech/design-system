## @soroush.design/styled-system@0.1.0

Responsive, theme-aware style props for CSS-in-JS, in TypeScript. You pick the style functions
a component needs, and its props resolve against the scales of your theme
([#154](https://github.com/soroush-tech/design-system/issues/154)).

### What it offers

- **Style-prop parsers by group.** `space` (`margin`, `padding`, `gap`), `color`, `layout`,
  `typography`, `flexbox`, `grid`, `background`, `border`, `position` and `shadow`, each also a
  subpath import (`@soroush.design/styled-system/space`). The root export adds the single-prop
  parsers (`width`, `fontSize`, `borderRadius`, ...).
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/styled-system/docs/api.md)
- **Responsive values.** Any prop takes an array (mapped by position onto the breakpoints) or an
  object keyed by breakpoint name, each from its size up (`{ xs: 'none', md: 'block' }`).
  `theme.breakpoints` is one scale; a key that starts at `0` is the base and writes no query.
  Every generated query is range syntax (`@media (width >= 840px)`), written in breakpoint order.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/styled-system/docs/responsive-styles.md)
- **Breakpoint and container queries.** `createMediaHelpers(breakpoints)` returns `up`, `down`,
  `only`, `between` and `not`; `createContainerQueries(breakpoints)` returns the same as
  `@container` rules, including for a named container. `cq<Name>` keys in a prop value
  (`p={{ xs: 2, cqSm: 4 }}`) write container queries, and `layout` takes `containerType` and
  `containerName`.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/styled-system/docs/breakpoints.md)
- **Layout grid.** The `layout` prop writes `theme.layout` per breakpoint as a page frame plus
  column tracks and a gutter, `span` sets how many columns an element takes, and
  `layoutGridStyles(theme, value, gap)` writes both from a style function.
- **`system()` and composition.** `system()` builds a parser for your own props, with aliases and
  theme scales; `compose()` joins parsers; `variant()`, `buttonStyle`, `textStyle` and
  `colorStyle` read variants from the theme.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/styled-system/docs/custom-props.md)
- **Theme-scale lookups.** `get()` and `themeGet` read a value from the theme by path
  (`'gray.0'`), and `css()` resolves a style object against the theme, expanding aliases and
  responsive values.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/styled-system/docs/css.md)
- **The prop filter.** The `should-forward-prop` subpath default-exports a filter that keeps
  style props off the DOM element, and names `createShouldForwardProp(propNames)` for your own
  list and `props` for the list of style props. Attributes React 19 added (`fetchPriority`,
  `popover`, `inert`) are forwarded. `pick` and `omit` from the `props` subpath keep or drop
  the style props of an object.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/styled-system/docs/guides/removing-props-from-html.md)
- **TypeScript.** The package ships its own declarations. Each group has a prop interface
  (`SpaceProps`, `ColorProps`, ...) that is generic over your `Theme`, so values are checked
  against the theme's scales.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/styled-system/docs/typescript.md)
- **Prop types.** The `prop-types` subpath builds React `propTypes` maps from the props a parser
  accepts.

### Packaging

- Dependencies: `csstype` (`^3.2.3`) and `@umber-style/is-prop-valid` (`^0.3.0`), the check for
  a valid attribute behind the prop filter.
- Peer: `prop-types` `^15.8.1`, optional. Only the `prop-types` subpath uses it.
- You bring your own CSS-in-JS library; the package carries none at runtime.
- ESM and CJS builds with declarations, and a subpath export for every group.
