## @soroush.tech/styled-system@6.0.0

Breakpoints become ranges with exact range-syntax queries, helpers to write them by hand,
container queries on the same scale, and a layout grid from `theme.layout`.
([#344](https://github.com/soroush-tech/core/issues/344))

### Added

- **Range-syntax queries** - every generated query is `@media (width >= <start>)`. A breakpoint
  that starts at 0 (`xs: '0px'`) is the base: it writes no query and holds until the next one.
- **Named breakpoints everywhere** - object values take breakpoint names, each from its size up
  (`{ xs: 'none', md: 'block' }`); arrays map by position onto the breakpoints in declared order.
  `css()` takes the same objects and arrays.
- **Query helpers** - `createMediaHelpers(breakpoints)` returns `up`, `down`, `only`, `between`
  and `not`, which return exact `@media` rules: `only('md')` is
  `@media (840px <= width < 1200px)`, `not('md')` is `@media (width < 840px), (width >= 1200px)`.
  [docs](https://github.com/soroush-tech/core/blob/main/packages/styled-system/docs/breakpoints.md#query-helpers)
- **Container queries** - `cq<Name>` keys (`p={{ xs: 2, cqSm: 4 }}`) write
  `@container (width >= 600px)` after the media blocks; `createContainerQueries(breakpoints)`
  gives the same helpers as `@container` rules, or for a named container with
  `containerQueries('sidebar').up(400)`. `containerType` and `containerName` style props in
  `layout`.
  [docs](https://github.com/soroush-tech/core/blob/main/packages/styled-system/docs/breakpoints.md#container-queries)
- **Layout grid** - the `layout` prop writes `theme.layout`'s content tokens per breakpoint, in
  two parts that compose: `layoutFrame` - the page frame: the margin, and a centred max width in
  fixed mode (computed inline margins, so a frame that is a grid or flex item still stretches) -
  and `layoutGrid` - the column tracks and the gutter on top. The gutter is the element's own
  `columnGap` or `gap` where it sets one - single, by name or as an array, from each breakpoint
  up - and the theme's elsewhere, so `column-gap` has one source. `layoutGridStyles(theme,
value, gap)` writes both in a style function. A field in the value replaces the theme's at
  every breakpoint (`{ maxWidth: '1280px' }`); an entry under a breakpoint name replaces it from
  that breakpoint up, mobile-first like every responsive prop (`{ lg: { columns: 16 } }`). The
  layout owns the tracks, inline padding and max width it writes.
- **`span`** - how many columns of a grid an element takes, responsive: `grid-column: span N`,
  or `span="full"` (`grid-column: 1 / -1`) for the whole row whatever the column count. Part of
  the `all` preset.
- **`createMediaQuery`**, **`breakpointQueries`**, **`responsiveQueries`**, **`containerKey`** and
  the **`Breakpoints`**, **`QueryHelpers`**, **`ContainerQueries`**, **`LayoutGridProps`**,
  **`LayoutFrameProps`**, **`LayoutGridGap`** types.

### Changed

- Media blocks follow breakpoint order, then container blocks; they were sorted by the text of
  the query. A parser follows the theme's breakpoints when the theme changes.
- A number breakpoint gets `px` (`768` is `768px`).

### BREAKING CHANGES

- **Generated media queries are range syntax.** `@media screen and (min-width: 40em)` is now
  `@media (width >= 40em)`: the same widths, without the `screen` media type, so the queries
  also apply when printing. Range syntax needs Chrome 104, Safari 16.4 or Firefox 63 and later;
  older browsers ignore the blocks. Migrate: nothing in code; update snapshot tests of generated
  CSS, and drop support for older browsers.
- **A breakpoint that starts at 0 is the base.** A scale such as `{ xs: '0px', sm: '600px' }`
  writes no query for `xs`, and arrays map position 0 onto it. A `0` breakpoint used to write
  `(min-width: 0)`.
- **`_` is no longer a typed responsive key.** At runtime a key that is not a breakpoint still
  falls back to the base value. Migrate: use your base breakpoint's name (`xs`).

### Upgrade

- From 5.x: see the breaking changes - styles are the same on screen in supported browsers.
