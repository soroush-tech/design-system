## @soroush.design/cli@0.2.0

### Added

- **`create [name]` starts a new app on the design system**
  ([#93](https://github.com/soroush-tech/design-system/issues/93)), in a new folder or an empty
  one, and never in a folder that holds anything. It asks for what it is not told - the name and
  the title typed, then the language, the package manager, the default color scheme and the sample
  data pages picked with the arrow keys
  ([#101](https://github.com/soroush-tech/design-system/issues/101)) - shows every choice, one a
  line, then every file and the install, and writes nothing before a yes; `--yes`, `--dry-run`, `--title`, `--framework`,
  `--ts`/`--js`, `--pm`, `--scheme` and `--no-git` answer ahead, and so does `--sample-data`,
  below. The folder keeps the name as typed, and the package name is its lowercase form:
  `testApp` is the package `test-app`
  ([#100](https://github.com/soroush-tech/design-system/issues/100)). It installs with the package
  manager picked, the one that ran it unless another is, with no scripts, and runs `git init` with
  no commit unless the folder is already in a repository. When a write or the install fails, it
  takes the new app away.
- **The Vike starter** ([#94](https://github.com/soroush-tech/design-system/issues/94)), the
  default of `create`, in TypeScript or JavaScript: an isomorphic app, each page prerendered at
  build time with the styles it uses, so it is drawn styled before any script runs, then moving
  between pages in the browser with no reload. `<Providers>` lives in the app's `+Layout`, under
  an app bar, as in every starter: the title, the links, and a light and dark switch; the themes
  are `init`'s. It has a home page, a second page and a
  404 page, built from the design system's components and tokens only.
- **The repository** ([#106](https://github.com/soroush-tech/design-system/issues/106)), asked
  after the package manager or given with `--layout`: a `workspace`, the default, with the app in
  `apps/web` (the package `@<name>/web`), an empty `services/`, and root scripts that run the
  app's through the package manager's workspaces; or `standalone`, the app alone.
- **The Astro starter** ([#107](https://github.com/soroush-tech/design-system/issues/107)), with
  `--framework astro` or the framework question, which comes after the rendering and offers the
  frameworks that render as picked. Its pages are `.astro` files whose React parts are islands:
  each renders inside the theme, the header draws the base styles once a page and holds the light
  and dark switch, and the islands share the scheme. It renders SSR, its default, or SSG, not
  isomorphic: with SSR the islands hydrate, and Astro's client router moves between pages with
  no reload by fetching the next page's HTML, keeping the design system's styles; with SSG, a
  page ships no JavaScript. It takes the sample data pages, and every library: each island is
  exported inside `withIsland`, which gives it the theme, the query client and the store; the
  counter and the greeting are islands of their own, rendered in the browser only.
- **The React Router starter** ([#111](https://github.com/soroush-tech/design-system/issues/111)),
  the one SPA starter, which `--render spa` or the SPA answer picks: React Router's data mode on
  Vite. Every page renders in a layout that holds the theme and the light and dark switch, the
  design system's `Link` moves between pages with no reload, and an unknown path shows the error
  page. With the sample data pages, a route's loader reads the items, or a query does with a data
  library. It takes every library, and has its tests.
- **Rendering** ([#102](https://github.com/soroush-tech/design-system/issues/102)), asked after the
  package manager or given with `--render`: `isomorphic`, the default; `ssr`
  ([#109](https://github.com/soroush-tech/design-system/issues/109)), where each page is rendered
  on a Node server on each request - Vike's own server, or Astro's Node adapter - which
  `npm start` runs; `spa`, a React Router app the browser renders; or `ssg`, where
  each page is HTML with no JavaScript, and no light and dark switch. All but SSR build to static
  files. In a workspace, the root's scripts are the app's own, `start` among them.
- **Libraries** ([#103](https://github.com/soroush-tech/design-system/issues/103)), asked by job
  after the framework ([#108](https://github.com/soroush-tech/design-system/issues/108)) - data
  fetching (TanStack Query or SWR), state management (zustand, Jotai or Redux Toolkit), then msw
  and React Hook Form with Zod
  ([#104](https://github.com/soroush-tech/design-system/issues/104)) - or given with `--with`.
  Each comes installed, wired in, and shown in the app: a counter on the home page, its count in
  the state library or in its own state; a greeting the home page reads from `src/data/api`
  through the data library; a validated form page that sends its values through it; a mock API
  that answers each of those calls while `VITE_MSW` is true, and from Node in the tests. With the sample data pages, the items come through the query, from the mock API.
  An SSG app takes no library, since it has no JavaScript in the browser.
- **Tests in every app**: Vitest and Testing Library, with `npm run test` checking the home
  page's title and counter - and, with msw, the greeting msw's Node server answers.
- **Sample data pages** ([#97](https://github.com/soroush-tech/design-system/issues/97)), with
  `--sample-data` or a yes to their question: `/items` lists six sample items and `/items/<id>`
  shows one, each page reading them in its `+data` at build time, with one page prerendered per
  item. A page reads its data with `useData()`. There is no data library to install.

### Changed

- The starters `create` writes are template files, in the package's `templates/` folder
  ([#110](https://github.com/soroush-tech/design-system/issues/110)): a TypeScript app per
  framework, with the JavaScript one made from it as the package is built, and a layer per
  rendering, the sample data and each library. The apps are the same; a README lists its libraries
  in the order `create` offers them, whatever order `--with` gave.
- The README is a short page that points to the docs, at
  [docs.soroush.tech/cli](https://docs.soroush.tech/cli/), which hold every question and option
  ([#105](https://github.com/soroush-tech/design-system/issues/105)). The docs and the help run
  the command line as `npx @soroush.design/cli`.
- The package entry re-exports `main` as its default export straight from where it is defined.
  Nothing changes for a caller: `import main from '@soroush.design/cli'` gets the same function.
- `Providers`, as `init` writes it, takes an optional `scheme` prop that picks the theme, the
  default scheme when it is left out. An app that renders `<Providers>` as before draws the same.
- An option of one command given to the other is refused by name: `init --js` says `--js` is an
  option of `create`.
- `--help` with a command shows that command's own options and examples, and so does a wrong
  option; with no command, it lists the commands.
