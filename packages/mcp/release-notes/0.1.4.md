## @soroush.design/mcp@0.1.4

Gild UI is `@gild-ui/react` at `0.1.0`
([#114](https://github.com/soroush-tech/design-system/issues/114)), and the server describes it
that way: every component is imported from it, and a markdown component from
`@gild-ui/react-markdown`:

```ts
import { Card } from '@gild-ui/react/Card'
import { Preview } from '@gild-ui/react-markdown/Preview'
```

The install line and the import examples in the plugin's skills name those packages too. The
server's own name, its tools and their inputs (including the `design-system` package value), and
the ids of its documents do not change.

The summary of the Next.js App Router providers guide now reads "ThemeProvider plus the style
registry for the Next.js App Router". The docs the server serves are read from the component
library's docs, which changed for the new styling engine (the providers file and the setup guide
use it), so the served content changes with them
([#112](https://github.com/soroush-tech/design-system/issues/112)).

The documentation is now at https://gild-ui.soroush.design: every `url` the server returns, the
`Docs:` line of its instructions and the package's `homepage` point there
([#148](https://github.com/soroush-tech/design-system/issues/148)).

The documentation pages have new addresses, and `url` follows them. A page's address is the path an
app imports it from: `https://gild-ui.soroush.design/react/Button/` for `@gild-ui/react/Button`,
`https://gild-ui.soroush.design/react/Table/TableCell/` for the member of a family,
`https://gild-ui.soroush.design/react/theme/` for the theme, and
`https://gild-ui.soroush.design/react/markdown/Editor/` for the markdown package's components
([#149](https://github.com/soroush-tech/design-system/issues/149)). The `package` input of
`list_components` still takes `design-system` and `markdown`, and a component record still says
`design-system` in its `pkg`: nothing a client sends or reads besides `url` changes.

The setup guide the server serves, and the plugin's, install `@gild-ui/react` and
`@gild-ui/core`, and show the theme file as an app writes it now: its themes gathered by
`defineThemes`, the registration of their types, and `registerBaseTheme` with the theme the app
starts in, so server components are themed.
