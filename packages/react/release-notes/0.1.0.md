## @soroush.design/react@0.1.0

The React design system of the soroush.design family, in one package: the components, the theme's
provider and hooks, and the styling system they are written in, on the UmberStyle styling engine
([#114](https://github.com/soroush-tech/design-system/issues/114),
[#162](https://github.com/soroush-tech/design-system/issues/162)). An app installs it and React,
and writes `@soroush.design/react` for the styling system and `@soroush.design/react/Button` for a
component.

### What it offers

- **Components, each on its own subpath**, so an app loads only what it imports
  (`@soroush.design/react/Button`, `.../Table/TableCell`, ...):
  - Layout and surfaces: `View`, `Flex`, `Grid`, `Paper`, `Card`, `AppBar`, `Drawer` with
    `DrawerToggle`, `Sidebar` with `SidebarItem`, `ScrollArea`, and `NavTree` with `NavGroup` and
    `NavLink`.
  - Content and data display: `Typography`, `Link`, `Image`, `Icon`, `Table`, `Quote`, `Avatar`,
    `Skeleton`, `Pagination`, `Chip`, `Badge`, `Breadcrumbs`, `Accordion`, and `Tabs` with `Tab`,
    `TabContext`, `TabList` and `TabPanel`.
  - Inputs and forms: `Button`, `ButtonGroup`, `Pressable`, `Fab`, `FabMenu`, `TextInput`,
    `NumberInput`, `NativeSelect`, `Select`, `Autocomplete`, `Checkbox`, `Radio`, `Switch`,
    `ToggleButton`, `Rating`, `RangeInput`, `TransferList`, `Form`, `FormControl`, `FormLabel` and
    `FormHelperText`.
  - Menus: `Menu`, `MenuList`, `MenuItem`, `MenuDivider`, `MenuItems` and `ContextMenu`, with
    submenus and menus built from data.
  - Feedback and overlays: `Alert`, `Snackbar`, `Tooltip`, `TooltipGroup`, `CircularProgress`,
    `LinearProgress`, `Modal`, `Popover`, `Portal`, `Backdrop` and `FocusTrap`.
  - Transitions: `Collapse`, `Fade`, `Grow`, `Slide` and `Zoom`, timed by `theme.transitions`.
    A user who asked for less motion sees every change at once.
- **The theme's provider and hooks.** `ThemeProvider` provides one theme and merges the optional
  `defaults`. `useTheme` returns it, `useDefaultProps` reads a component's
  `theme.components[name].defaultProps`, `withTheme` hands it to a class component, `useMediaQuery`
  answers a media query for what a style cannot do, and `LayoutProvider` changes the layout tokens
  for a part of the page. The tokens, `baseTheme` and `createTheme` are
  `@soroush.design/core`'s, imported from `@soroush.design/core/theme`. `theme.defaults` and the
  provider's `defaults` prop replace the literal fallbacks of a component, such as `size` and
  `variant`. `ThemeProvider` takes any theme `defineThemes` returns and rejects a theme with a key the
  registered themes lack; in development it warns, once per problem, about a component, slot or
  default prop in the theme's `components` that the catalog does not know. `useTheme` and
  `withTheme` hand the registered theme's type.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react/docs/theming.md)
- **The styling system.** `styled`, `css`, `keyframes` and `Global` come from the package root,
  typed against the theme and configured with the prefix `soroush`, the style memo and the raw
  theme keys. `styled(tag, { name, slot })` makes a component customizable through
  `theme.components`. A colour at an opacity is `alpha(color, opacity)`, a negative length is
  `negate(length)`, and a number that changes at runtime (a slider's thumb, a pan) is
  `useStyleValue`, which writes one class and changes a CSS variable: no style attribute is
  rendered, and a token is never glued to a hex digit or a unit.
  `useStyle`, `withStyles` and `StylesConsumer` are the custom CSS layer. An app can build its own
  components on the same tokens with none of ours, server-rendered with the same class names and
  variables. `/engine` has `globalStyles` (the base reset), `CacheProvider`, `styleCache` and
  `createCache` for apps that render their own styles or extract critical CSS.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react/docs/style.md)
- **One path for each name.** Every name of the styling system is also an entry point of its own:
  `@soroush.design/react/ThemeProvider`, `/LayoutProvider`, `/useTheme`, `/useDefaultProps`,
  `/useMediaQuery`, `/withTheme`, `/styled`, `/css`, `/keyframes`, `/Global`, `/useStyle`,
  `/withStyles` and `/StylesConsumer`. Each configures the engine on its own, so an app that
  imports only `keyframes` gets the prefix and the style memo.
- **Layout from the theme.** `theme.breakpoints` holds the window size classes (`xs`, `sm`, `md`,
  `lg`, `xl`) with query helpers (`up`, `down`, `only`, `between`, `not`, container queries).
  `theme.layout` holds the layout tokens per class. The `layout` prop on `View`-based components
  gives the page frame, `span` sets the columns an element takes in a grid, and `LayoutProvider`
  adjusts the layout for a part of the page. Everything responsive is CSS, so pages work with
  JavaScript off.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react/docs/theming.md#breakpoints-and-layout)
- **Per-component customization through `theme.components`.** A theme sets `defaultProps`, styles
  each slot of a component with `styleOverrides` callbacks that receive `{ theme, ownerState }`,
  and adds `variants`. A theme that does not use it pays nothing. Each component's entry point
  exports the types of its own: `ButtonOwnerState`, `ButtonSlot` and `ButtonThemeConfig`, and the
  package exports `ThemeComponents`, a plain interface generated from the component folders, which
  an app checks its looks against with `satisfies ThemeComponents`: a misspelt `ownerState` field,
  a slot a component does not have, or a default prop of the wrong kind is an error. No component
  declares into another module.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react/docs/customization.md)
- **The catalog.** `.../catalog` describes every component as plain data for tools that place and
  write components: its category, its subpath, its named looks, the props a picker offers and the
  events worth offering. It loads in plain Node, with no DOM and no React, and survives JSON
  unchanged.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react/docs/catalog.md)
- **Server rendering and static generation.** The outermost `ThemeProvider` renders no element: it
  declares the theme as CSS variables on `:root`. Server output carries the base styles and theme
  variables first, then the classes, and only the theme variables a page uses are declared.
  `ThemeProvider` and `LayoutProvider` give the engine the same theme object for the same input on
  every render, so a server render declares the theme's tokens once. `Drawer` is an HTML popover,
  so it opens and closes without JavaScript, and the groups of a `NavTree` fold without it. Under a
  style policy that allows style elements by nonce, the engine's own style element carries the
  nonce of the page's scripts. The engine writes to `styleCache`, the one cache of the library, so a
  `CacheProvider` over `styleCache`, the extraction with `createInstance(styleCache)` and the
  engine's own styles share it, and a development message is logged once, not once for each of two
  caches of the same prefix.
- **`text.inherit` is the keyword.** The base theme's `text.inherit` is `inherit`; as a CSS variable it
  would take the value of the same variable on the parent - nothing - so only `color` worked, by
  inheritance, and `background-color` was transparent. The engine now writes the keyword itself, so
  `theme.text.inherit` is the parent's value for any property, and the development warning about
  `--soroush-text-inherit` is gone.
- **Set up with one command.** `npx @soroush.design/cli init` sets the package up in a
  client-rendered React app, and `create` starts a new one. The package itself has no command and
  installs no command line.
- **Server components.** In a Next.js App Router app the static components (`Typography`, `View`,
  `Flex`, `Grid`, `Paper`, `Card`, `Skeleton`, `Icon`, `Link`, `Badge`, `AppBar`, `Quote`, the
  progress indicators and `Fab`) render in a server component, and the interactive ones carry
  `'use client'` in the build, so a server component imports them all. Each component's README says
  which it is. `registerBaseTheme(theme)` (from `.../ThemeProvider`) gives server components the
  app's `components`, `defaults` and tokens; an app that registers nothing renders them with the
  built-in theme, which the engine has as its base theme from the start. An app calls it once, in the module that defines its themes, with the theme
  its provider starts in. The setup guide has the layout; no style registry is needed.
- **Accessibility.** Menus, tabs, lists, the rating and the accordion group own their keyboard.
  Texts that a screen reader reads, such as the labels of `Autocomplete`, `NumberInput` and
  `Snackbar` controls, are props, so the app writes them in its own language. The text of an
  `Alert` is checked against AA for each severity, a `Tooltip` stays hoverable (WCAG 1.4.13), and
  transitions and the `Sidebar` honour `prefers-reduced-motion`.
- **TypeScript.** The package ships declarations for every entry point. The scales of the theme
  and the variants of a component are typed from the theme the app registers. Style props come
  from `@soroush.tech/styled-system` (`^6.0.3`) and are typed on every component.
- **Testing helpers.** `.../testing` has `installPopover()`, a stand-in for the Popover API in
  jsdom unit tests.
- **Use it with AI tools.** The hosted MCP server at `https://mcp.soroush.design/mcp`, the
  house-style skill (`npx skills add soroush-tech/design-system`) and the Claude Code plugin give
  an assistant the components, the tokens and the setup guides.

### Packaging

- Peers: `react` and `react-dom` `^19.2.8`. Nothing else is installed alongside.
- Dependencies: the UmberStyle engine (`@umber-style/cache`, `@umber-style/react` and
  `@umber-style/styled`, `^0.8.0`), `@soroush.design/core`, `@soroush.tech/styled-system` (`^6.0.3`, from npm) and
  `@soroush.design/react-hooks`. They are packages of their own and the build imports them by
  name, so an app has one copy of each: one theme context and one engine configuration.
- ESM and CJS builds with declarations, and a subpath export for every component folder and every
  name of the styling system.
- The markdown editor and renderer are `@soroush.design/react-markdown`, which has this package as
  a peer.
