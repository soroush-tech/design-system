## @soroush.tech/design-system@3.0.0

The styling engine is now UmberStyle
([#112](https://github.com/soroush-tech/design-system/issues/112)). Components, their props,
`styled`, `css`, `keyframes`, `ThemeProvider`, `useTheme`, `createTheme` and `theme.components`
overrides keep their names and behaviour. An app that only uses components and the theme
changes nothing except its React version, which must now be 19.2 or later.

### Changed

- **The outermost `ThemeProvider` renders no element.** It declares the theme as CSS variables on
  `:root`. A nested `ThemeProvider` with a theme renders a wrapper element with
  `display: contents`. Portals keep a nested theme. Switching the outermost theme re-renders
  nothing.
- **Per-page CSS in server output is in two style elements:** the base styles and theme
  variables first, then the classes. Only the theme variables a page uses are declared.
- **Browsers.** Vendor-prefixed forms are written for the browsers of the last two years: Chrome
  and Edge 132, Firefox 133, Safari and iOS Safari 18.2, or later.
- The engine pieces the package exports are the same as before: `styled`, `css` and `keyframes`
  from `@soroush.tech/design-system`, and `createCache`, `Global`, `CacheProvider`, `styleCache`
  and `globalStyles` from `@soroush.tech/design-system/engine`. The engine's own API
  (`StyleSheet`, `useStyle`) is not exported by this package in this version.

### Fixed

- **`borderColor` on `Table`, `TableBody`, `TableCell`, `TableFooter`, `TableHead`, `TableRow`
  and `View`.** The prop is read through the theme's `border` scale. A second style-prop parser
  also knew the name and wrote the raw token name (`light`) instead of the colour. The theme's
  own mapping now wins.

### BREAKING CHANGES

- **React 18 is no longer supported. React 19.2 or later is required.** Affected: every app.
  Edit: set `react` and `react-dom` to `^19.2.8` or later in your `package.json`.
- **Package names for apps with their own server-rendering set-up.** Affected: apps that
  import the previous engine's packages themselves. Edit these imports, then remove the
  previous engine's packages from your own `package.json`:
  - The previous engine's cache package (its default import, `createCache`). Use the design
    system's own, or the engine's:

    ```ts
    import { createCache } from '@soroush.tech/design-system/engine'
    // or: import createCache from '@umber-style/cache'
    ```

  - The previous engine's server package, imported from its `create-instance` file (default
    export, the same four functions). Use `@umber-style/server`, and add it to your
    dependencies:

    ```ts
    import createServer from '@umber-style/server/create-instance'
    ```

  - The previous engine's class-name package. Use `@umber-style/css`.

- **Style elements have new attributes.** Server-rendered elements carry
  `data-umber="soroush ..."` and `data-umber="soroush-global ..."`. The live element in the
  browser is `<style data-style="soroush">`. Class names have the form
  `soroush-<labels>-<hash>`. Affected: code or tests that select style elements, or class names,
  by the previous attribute or form. Edit: select by the attributes above.
- **`style` on a design-system component becomes a class, not a `style` attribute.** Rendering
  is the same. Affected: code or tests that read `element.style`. Edit: read
  `getComputedStyle(element)` instead.
- **Inside a style function, a theme token is a CSS variable reference**
  (`var(--soroush-palette-primary-main)`), not the value. Common string forms keep working: a
  hex alpha suffix, a leading minus, a unit after a token. Affected: code that uses a token as a
  key or an index into another object. Edit: read the value from `useTheme()`, which still
  returns real values.
- **Two style-prop parsers that set the same property no longer both write a declaration. The
  later one wins.** Affected: components of your own that list two parsers for one property.
  Edit: put the parser whose mapping you want last. (This is what the `borderColor` fix above
  corrects inside the design system.)
- **The content security policy nonce on the cache is not available in this version.** The
  setup guide's paragraph on it is removed. There is no date for it.

### Migrating from 2.x

1. Update React: `react` and `react-dom` to `^19.2.8` or later.
2. Update the package: `"@soroush.tech/design-system": "^3.0.0"`. If you use
   `@soroush.tech/markdown`, it works with this version from 1.4.0.
3. Remove the previous engine's packages from your own `package.json`, if you added them. The
   design system brings the engine (the `@umber-style/*` packages) as its own dependency.
4. If you render on the server yourself, change the imports as shown under the package names
   above, and add `@umber-style/server` if you use it.
5. For the Next.js App Router, change your `providers.tsx` as the setup guide shows: `createCache`
   comes from `@soroush.tech/design-system/engine`, and the style element carries `data-umber`.
   The rest of the file stays, and so may a cache key of your own. Tested on Next.js 16.4. One
   known fault in the engine's 0.2.0: a theme given to the outermost `ThemeProvider` while the
   page is still streaming (a light and dark switch made before the last chunk arrives) goes
   back to the earlier theme when that chunk arrives, until the next switch. A switch made after
   the page has finished streaming works.
6. Search your code and tests for the previous style attribute, for `.style` reads on design
   system elements, and for theme tokens used as keys. Change them as described above.
7. If you use a content security policy nonce on the cache, note that it is not available in
   this version.
8. Check your pages in a browser from the last two years (see Changed).

### Packaging

- `react` and `react-dom` peer ranges narrow from `^18.0.0 || ^19.0.0` to `^19.2.8`.
- The styling engine is now the `@umber-style/cache`, `@umber-style/react`,
  `@umber-style/styled` and `@umber-style/css` packages, `^0.2.0`, as dependencies.
