## @soroush.tech/design-system@2.0.0

The theme holds the page's layout system - the window size classes as breakpoints, and the
layout tokens per class - so an app and the design studio work from the same values. Everything
responsive is CSS: pages work with JavaScript off.
([#344](https://github.com/soroush-tech/core/issues/344))

Action menus - a trigger and the list of commands it opens, with its own keyboard, and `MenuItem`
as a menu row ([#11](https://github.com/soroush-tech/design-system/issues/11)); tabs, a row of
tabs with content of its own around it, as a tablist or a navigation
([#15](https://github.com/soroush-tech/design-system/issues/15)); and a component catalog for
tools, shipped with the package ([#21](https://github.com/soroush-tech/design-system/issues/21)).
Inputs - a rating and a number field first ([#31](https://github.com/soroush-tech/design-system/issues/31)).
Breadcrumbs, the first of the navigation components
([#29](https://github.com/soroush-tech/design-system/issues/29)).

### Added

- **More spacing steps** - `theme.space` gains `0.125` (1px), `0.25` (2px), `0.75` (6px), `1.25`
  (10px) and `1.75` (14px), and `spacing()` rounds to whole pixels with a 1px floor for any
  non-zero step (every default step is exact on the 8px unit). `0.125` and `0.25` are for
  hairline gaps; lines below 4px are border widths.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/docs/theming.md#the-spacing-scale)
- **`theme.breakpoints`** - each key a range, from its value until the next: `xs` 0-599px
  (compact, the base), `sm` 600-839 (medium), `md` 840-1199 (expanded), `lg` 1200-1599 (large),
  `xl` 1600+ (extra-large). Responsive props use them by name (`p={{ xs: 2, md: 4 }}`), by
  position (`p={[2, 3, 4]}`) or as container queries (`cqSm`). `BreakpointOverrides` adds,
  renames or removes breakpoints with type safety.
  [docs](https://github.com/soroush-tech/core/blob/main/packages/design-system/docs/theming.md#breakpoints-and-layout)
- **Query helpers** - `theme.breakpoints.up` / `down` / `only` / `between` / `not` and
  `theme.breakpoints.containerQueries`, rebuilt from the theme's own sizes by `createTheme` and
  `ThemeProvider`; plain `up`, `down`, `only`, `between`, `not` and `containerQueries` exports
  for `baseTheme`, and `withBreakpointHelpers` for a scale of your own.
- **`theme.layout`** - layout tokens per window class: `content` (columns 1-16, margin and gutter
  as `theme.space` keys, fluid or fixed with `maxWidth`), `panels` (`start` / `end`, each
  `inline`, `overlay`, `collapsed` or `hidden` with `width` and `railWidth`) and `bars` (a 64px
  top bar on every class). `baseTheme` uses 4 / 8 / 12 / 12 / 12 columns, the start panel as a
  72px rail from `sm` and inline at `xl`, the end panel as an overlay at `md` and `lg` and inline
  at `xl`.
- **`layout` prop** - on any `View`-based component, `Flex` included, it is the page frame: the
  theme's margin and, in fixed mode, its centred max width per class - the element keeps its own
  display (`<View as="article" layout>`, `<Flex layout gap={3}>`). On `Grid` it adds the column
  tracks. The grid's own `gap` / `columnGap` is its gutter - single or responsive - and the
  theme's gutter applies where it is not set. `layout={{ lg: { columns: 16 } }}` replaces the
  theme's columns from `lg` up, `layout={{ maxWidth: '1280px' }}` its max width at every class,
  and the two mix. A frame spans its parent in any context (a grid item, a flex column or row),
  capped by its max width in fixed mode, rather than shrinking to its content.
- **`DrawerToggle`** - the button that opens and closes a `Drawer` through `popovertarget`.
- **`LayoutProvider`** - a page-level layout on the `./theme` subpath:
  `<LayoutProvider layout={{ lg: { content: { maxWidth: '1376px' } } }}>` merges the page's values
  onto `theme.layout` for everything inside, field by field and mobile-first, and changes nothing
  else - colours and light/dark switching stay the surrounding theme's. Providers nest.
- **`@soroush.tech/design-system/testing`** - `installPopover()`, a Popover API stand-in for
  jsdom unit tests: show, hide, the `toggle` event, Escape and `popovertarget` clicks. It
  returns a function that removes it, and does nothing where the real API exists.
- **`span` on `View`** - how many columns of a grid an element takes (`span={{ xs: 4, md: 6 }}`),
  or `span="full"` for the whole row whatever the column count; every `View`-based component
  takes it.
- **`Menu`** - a trigger and the `MenuList` it opens. Not modal: nothing is laid over the page and
  focus isn't trapped. The list is placed `position: fixed` under the trigger (`align` start or
  end, mirrored right to left), flips above it near the bottom of the window, stays
  `marginThreshold` inside it and follows the trigger on scroll and resize - so a panel's
  overflow can't clip it - while staying inside the menu's own box in the DOM. ArrowDown/ArrowUp
  on the trigger open it; Escape, a chosen row, the trigger again, or focus leaving close it
  (`onClose(event, reason)`), focus going back to the trigger unless it left. Uncontrolled
  (`defaultOpen`) or controlled (`isOpen`, `onOpen`), with `onStep(-1 | 1)` for a menu bar;
  `emptyLabel` for a menu with no rows; `elevation` and `layer`.
  ([#13](https://github.com/soroush-tech/design-system/issues/13))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Menu/Menu/README.md)
- **`MenuList`** - a `role="menu"` list that owns the keyboard: the arrow keys, Home and End move
  focus between its own rows, skipping disabled ones and wrapping (`shouldWrap`); typing jumps to
  a row by its label. `shouldAutoFocus` focuses the checked row, or the first enabled one.
  `onSelect(value)` reports the chosen row; `color`, `textColor`, `size` and `dense` set every
  row's defaults. Rows are found by their nearest `role="menu"`, so a nested list keeps its own.
  ([#12](https://github.com/soroush-tech/design-system/issues/12))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Menu/MenuList/README.md)
- **`MenuItem` menu rows** - inside a `MenuList`, a `MenuItem` is a `menuitem`, `menuitemradio`
  or `menuitemcheckbox` (`role`), with `selected` as `aria-checked`, a leading `startIcon` column
  kept on every row, a trailing `shortcut` (also `aria-keyshortcuts`), a `note` that tells why a
  disabled row is off, `secondaryAction` - a control of its own beside it, the pointer's, hidden
  from assistive technology - and `onClick`. The pointer moves focus as it goes, so one row is
  highlighted at a time. Inside a `Select` it is the same `option` row as before.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/MenuItem/README.md)
- **Submenus** - `submenu` on a `MenuItem` opens a nested `MenuList` beside its row, to any
  depth; `null` or `[]` is an empty one, which shows `emptyLabel`. The row and its submenu sit
  side by side in a `role="none"` entry, the row `aria-haspopup="menu"` with `aria-expanded` and
  a chevron that mirrors right to left. Focus decides the submenu: a focused row - by key or by
  the pointer - has it open, a sibling taking focus closes it. Right, Enter or Space go in; Left
  or Escape come back (swapped right to left). A choice in a submenu is the outer list's
  `onSelect` and closes the whole `Menu`. Placed beside the row on the side away from the menu's
  `align` edge, or the other side when the window has no room - its own submenus then go on
  that way, never back over the menu; with room on neither side, under the row (or over it),
  never covering it.
  ([#14](https://github.com/soroush-tech/design-system/issues/14))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/MenuItem/README.md#submenus)
- **`ContextMenu`** - the same list opened by a right-click over its `target`, at the pointer,
  or by the context-menu key / Shift+F10 at the focused element; placed and closed as `Menu` is,
  with focus going back to where it was. The browser's own menu is held back only when this one
  opens. ([#20](https://github.com/soroush-tech/design-system/issues/20))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Menu/ContextMenu/README.md)
- **Menus from data** - `MenuItems` renders rows from `MenuItemData[]` (rows, `{ type: 'divider' }`,
  submenus as nested entries), and `Menu` and `ContextMenu` take the same array as `items`.
  ([#20](https://github.com/soroush-tech/design-system/issues/20))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Menu/MenuItems/README.md)
- **`MenuDivider`** - a `role="separator"` line between groups of rows.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Menu/MenuDivider/README.md)
- **One subpath for the menus** - `Menu`, `MenuList`, `MenuDivider`, `MenuItems` and
  `ContextMenu` are one family, imported from `@soroush.tech/design-system/Menu`, as `Table`'s
  parts are. It also exports `MenuListContext` and `useMenuListContext` - present inside a
  `MenuList`, the rows' look and how a row reports its choice - and the `MenuItemValue` and
  `MenuItemData` types.
- **Theme customization** - `theme.components.Menu` (`root`, `paper`), `.ContextMenu` (`root`,
  `paper` - its surface alone, over `Menu`'s), `.MenuList` and `.MenuDivider`, and `MenuItem`'s
  new `startIcon`, `label`, `shortcut`, `submenuIcon`, `entry` and `secondaryAction` slots. `defaultProps` for
  `Menu` (`align`, `marginThreshold`, `elevation`, `layer` and the rows' look), `ContextMenu`,
  `MenuList` (`shouldWrap` and the rows' look) and `MenuItem` - a list's own values win.
- **`Tabs`, `Tab`** - a row of tabs. A `tablist` by default: one tab in the page's tab order,
  the arrow keys of its `orientation` moving between tabs (skipping disabled ones, coming round,
  swapped right to left), Home/End, Enter or Space selecting - or moving focus selecting, with
  `shouldSelectOnFocus`. `as="nav"` gives the same look as a navigation of buttons or links,
  marked `aria-current="page"`. `value` / `defaultValue` / `onChange`, `null` for none; a tab
  without a value takes its position. `variant` `underline` (a sliding indicator), `boxed`
  (outlined on a raised ground) or `enclosed` (outlined on its top and sides, open onto the
  divider) - an augmentable `TabsVariants`; `color`, `textColor`, `size`, `fullWidth`,
  `isCentered`; `hasDivider`, a line the row's whole length - round the selected tab when
  enclosed, which without it is outlined all round. `startContent` / `endContent` hold the
  row's own components outside the arrow keys, a space from the tabs. A `Tab` takes `label`, an
  `icon` placed by `iconPosition` (`top` by default) at the size it is given - every label in a
  row on one line - `isWrapped`, `disabled`, `href` and `as`. `action.updateIndicator()`
  re-measures.
  ([#16](https://github.com/soroush-tech/design-system/issues/16))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Tabs/Tabs/README.md) ·
  [`Tab`](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Tabs/Tab/README.md)
- **Closable tabs** - a `Tab` with a `closeLabel` has a ✕ of its own beside it, out of the tab
  order, shown on the selected tab and under the pointer and keeping its room on the others; it,
  a middle click and Delete fire `Tabs`' `onTabClose(value)`. The ✕ is the pointer's - a tablist
  owns tabs alone, so it is hidden from assistive technology - and the tab announces Delete
  (`aria-keyshortcuts`). `secondaryAction` puts a control
  of the tab's own after its label. The selected outline and raised ground are drawn around the
  whole tab, its controls included. ([#17](https://github.com/soroush-tech/design-system/issues/17))
- **Scrolling tabs** - `overflowBehavior="scroll"` scrolls the list along its orientation when its
  tabs don't fit, with `scrollButtons` `auto` (each shown while tabs are out of view its way),
  `always` (disabled at an end) or `never`; hidden on narrow screens unless
  `shouldShowScrollButtonsOnMobile`, the scrollbar hidden unless `hasVisibleScrollbar`. A button
  scrolls a view's worth (smoothly, unless reduced motion is preferred), the selected tab is
  scrolled fully into view, and right to left everything is mirrored. `action.updateOverflow()`.
  The buttons are `TabScrollButton`s - exported, and replaced with `slots={{ scrollButton }}`.
  ([#19](https://github.com/soroush-tech/design-system/issues/19))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Tabs/TabScrollButton/README.md)
- **Tabs that don't fit go to a menu** - `overflowBehavior="menu"` draws the tabs that fit whole,
  in order - the selected one, or the first enabled one, always - and lists the rest in a `Menu`
  behind a button at the list's end, named by `overflowLabel`. Nothing scrolls and no tab is cut by
  the edge. Choosing a row selects its tab, which brings it into the row; a closable tab's row has
  its ✕ beside it, and Delete on the row closes it too. Measured after every render and whenever the list resizes, down a column too;
  prerendered, every tab is drawn. `action.updateOverflow()` measures again.
  ([#18](https://github.com/soroush-tech/design-system/issues/18))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Tabs/Tabs/README.md#tabs-that-dont-fit-go-to-a-menu)
- **`TabContext`, `TabList`, `TabPanel`** - a `TabContext` holds the value (`value` /
  `defaultValue` / `onChange`) for a `TabList` - the `Tabs` that shows it, each tab linked to
  its panel - and the `TabPanel`s beside it, wherever they sit; a `TabPanel` is a
  `role="tabpanel"` named by its tab, shown while it is selected (`shouldKeepMounted` keeps
  hidden content mounted, `bg` its ground).
  [`TabContext`](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Tabs/TabContext/README.md) ·
  [`TabList`](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Tabs/TabList/README.md) ·
  [`TabPanel`](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Tabs/TabPanel/README.md)
- **One subpath for the tabs** - `Tabs`, `Tab`, `TabContext`, `TabList`, `TabPanel` and
  `TabScrollButton` are imported from `@soroush.tech/design-system/Tabs`.
- **Grounds** - `bg` colors the tab strip and `selectedBg` the selected tab (`paper` by default in
  the boxed look, and in the enclosed look without a divider - which draws no border then); give
  the `TabPanel` the same `bg` and tab and panel read as one. A `Tab` takes its own `bg` while
  unselected, and `borderRadius` - only the corners away from the divider when enclosed; a
  `TabPanel` takes `borderRadius` too.
- **Theme customization** - `theme.components.Tabs` (`root`, `list`, `indicator`,
  `startContent`, `endContent`, `scrollButton`, `overflowButton`, `overflowClose`, with
  `defaultProps` for `variant` / `color` / `size` / `hasDivider` / `selectedBg`), `.Tab` (`root`,
  `label`, `icon`, `secondaryAction`, `close`, with `defaultProps` for `isWrapped` / `bg` /
  `borderRadius` / `color` / `textColor` / `size` / `selectedBg`), `.TabScrollButton`
  (`defaultProps` for `color` / `textColor`) and `.TabPanel` (`defaultProps` for
  `shouldKeepMounted`).
- **A tab's own look** - like a table cell, a `Tab` takes its row's `color`, `textColor`, `size`
  and `selectedBg`, and its own value wins: the tab's prop, then the row's, then
  `theme.components.Tab.defaultProps`, then the row's default. The underline indicator, the
  enclosed divider under every other tab and the overflow button take the selected tab's color. A
  `TabScrollButton` takes `color` (its stretch of the divider) and `textColor` (its chevron) the
  same way. A tab's `size` sets its type and its sides; across a row every tab takes the row's
  tallest top and bottom padding, so a smaller tab keeps its label on the others' line.
- **`Breadcrumbs`** - the trail of links from a site's root to the current page: a `nav` landmark
  named by `aria-label`, its crumbs - the app's `Link`s and `Typography` - an ordered list with an
  `aria-hidden` `separator` between two (`/` by default; an icon separator mirrors right to left).
  Past `maxItems` (8) only the first `itemsBeforeCollapse` and last `itemsAfterCollapse` crumbs show,
  with a button named by `expandLabel` that shows the whole trail and moves focus to its first link;
  `slots.collapsedIcon` and `slotProps.collapsedIcon` replace its icon. The root is a `Typography`:
  `color` (`secondary` by default), `typography` - its variant - `align`, `as`. `theme.components.Breadcrumbs` styles
  `root`, `list`, `item`, `separator`, `collapsed` and `collapsedIcon`, with `defaultProps` for
  `separator`, `maxItems`, `itemsBeforeCollapse`, `itemsAfterCollapse`, `expandLabel` - a trail's
  language - and `color`. `Icon` gains `more_horiz`.
  ([#30](https://github.com/soroush-tech/design-system/issues/30))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Breadcrumbs/README.md)
- **`Rating`** - a row of icons the user sets as a rating, or a read-only display of one. A group of
  visually hidden native radios, so the keys (Tab to the rating, the arrows to change it),
  assistive technology and forms work as the platform's. `value` / `defaultValue` / `onChange`
  (`null` when cleared), `max`, `precision` (`0.5` for halves - the rating is rounded to it),
  `highlightSelectedOnly`, `icon` / `emptyIcon`, `size`, `color`, `readOnly` (one `role="img"`),
  `disabled`, `required`, `error`, `name`. Hovering previews the value (`onChangeActive`), pressing
  the chosen item clears it. Every label is the app's: `getLabelText` names each item and
  `emptyLabelText` the "no rating" radio. In a `FormControl` it takes the field's size, color, error,
  disabled and required state, and its `FormLabel` names the group. `theme.components.Rating` styles
  `root`, `item`, `icon`, `decimal`, `input`, `text` and `emptyLabel`, with `defaultProps` for `max`,
  `precision`, `highlightSelectedOnly`, `size` and `color`. `Icon` gains `star` and `star_border`;
  `FormLabel` registers with its `FormControl` (`labelId` from `useFormControl`), the way
  `FormHelperText` does.
  ([#32](https://github.com/soroush-tech/design-system/issues/32))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Rating/README.md)
- **`NumberField`** - a field for a number. A text input - so what is typed is the user's until it is
  settled - that reads and writes the number in its locale (`locale`, `format` - an
  `Intl.NumberFormat`, a percent read as its fraction), clamps it to `min`/`max`, and steps by the
  arrow keys (`step`; Alt `smallStep`; Shift `largeStep`), Home/End, the wheel
  (`shouldScrubOnWheel`) and buttons that repeat while held (`spinButtons`: `stacked`, `sides` or
  `none`). `value` / `defaultValue` / `onChange` (as typed) / `onChangeCommitted` (on blur, Enter or a
  step), `shouldSnapOnStep`, `variant`, `size`, `color`, `error`, `disabled`, `readOnly`,
  `required`, `fullWidth`, `name` (a hidden input carries the raw number to a form). A
  `role="spinbutton"`; the buttons' names (`incrementLabel`, `decrementLabel`) are the app's. In a
  `FormControl` it takes the field's size, color, error, disabled and required state, and its
  `FormLabel` targets the field. `theme.components.NumberField` styles `root`, `input`,
  `spinButtons`, `increment` and `decrement`, with `defaultProps` for the frame, the steps and the
  two labels. `Icon` gains `add` and `remove`.
  ([#33](https://github.com/soroush-tech/design-system/issues/33))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/NumberField/README.md)
- **`InputRange`** - a slider: one value on a range, or a thumb for each value of an array. Each
  thumb is a visually hidden native `<input type="range">`, so the arrows, Page, Home and End,
  assistive technology and forms work as the platform's; the pointer drags a thumb, touch included.
  `value` / `defaultValue` / `onChange(event, value, activeThumb)` / `onChangeCommitted`, `min`,
  `max`, `step` (`null` limits the value to `marks`), `shiftStep`, `marks`, `orientation`, `track`
  (`'normal'`, `'inverted'` or `false`), `scale`, `valueLabel` and `formatValueLabel`,
  `shouldSwapThumbs`, `size`, `color`, `error`, `disabled`, `name`. Every name is the app's:
  `getAriaLabel` for each thumb and `getAriaValueText` for its value. In a `FormControl` it takes
  the field's size, color, error and disabled state, and its `FormLabel` targets and names the
  thumbs. `theme.components.InputRange` styles `root`, `rail`, `track`, `thumb`, `mark`,
  `markLabel`, `valueLabel` and `input`.
  ([#34](https://github.com/soroush-tech/design-system/issues/34))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/InputRange/README.md)
- **`TransferList`** - two lists, and the buttons that move the checked items from one to the other.
  Data-driven: `items` (`{ value, label, disabled? }`), `value` / `defaultValue` (the values on the
  right) and `onChange`. Each list is a `role="list"` of rows whose checkbox is the row - one tab
  stop, named by its label; move right and left act on the checked items and are off while none is
  checked, `shouldShowMoveAll` adds the buttons that move every enabled item, and `hasSelectAll`
  adds a header checkbox - all, some or none - with the count (`getCountLabel`). A disabled item
  stays where it is. Every name is the app's: `leftLabel`, `rightLabel` and the four buttons'
  labels. In a `FormControl` it takes the field's size, color, error and disabled state, and its
  `FormLabel` names the group. `theme.components.TransferList` styles `root`, `list`, `header`,
  `title`, `count`, `items`, `item`, `controls` and `icon`, with `defaultProps` for the buttons'
  labels, the move-all and select-all switches, `size` and `color`.
  ([#35](https://github.com/soroush-tech/design-system/issues/35))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/TransferList/README.md)
- **`Collapse`, `Fade`, `Grow`, `Slide` and `Zoom`** - show and hide content by moving it. Each takes
  `isShown`, `shouldAppear`, `shouldMountOnEnter`, `shouldUnmountOnExit`, `timeout` (a number or
  `{ enter, exit }`), `easing` and the lifecycle callbacks (`onEnter` ... `onExited`, each told the
  node), over one shared `useTransition`. `Fade`, `Grow`, `Slide` (with `direction`, mirrored right
  to left, measured from where the child sits) and `Zoom` wrap one child that holds a `ref` and
  takes a `style`; out, it is hidden. `Collapse` opens by the height - or, `orientation="horizontal"`,
  the width - of its content, measured as it moves and left to the content once open, with a
  `collapsedSize`. Time and easing come from the new `theme.transitions` (`duration`: `short`,
  `standard`, `long`; `easing`: `standard`, `enter`, `exit`); a user who asked for less motion sees
  it all change at once, and the callbacks still fire. `theme.components.Collapse` styles `root`,
  `wrapper` and `inner`, with `defaultProps` for its orientation, collapsed size, time, easing and
  `shouldAppear`.
  ([#41](https://github.com/soroush-tech/design-system/issues/41))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Collapse/README.md)
- **`Accordion`** - a heading that opens and closes a region: `AccordionSummary` (a button in a
  heading - `headingLevel`, `expandIcon`), `AccordionDetails`, `AccordionActions` and
  `AccordionGroup`. The summary carries `aria-expanded` and `aria-controls`; the rest is a

  closed it owns, until `isExpanded` takes it over (`onChange(event, isExpanded)`);
  `defaultExpanded`, `disabled` and `hasGutters`. In an `AccordionGroup` the arrows, Home and End
  move between summaries (one that is off is skipped), `isExclusive` keeps one open at a time and
  `variant="attached"` joins them into one block with no gap.
  `theme.components` styles `Accordion` (`root`, `region`), `AccordionSummary` (`root`, `button`,
  `content`, `icon`) and the `root` of the rest, with `defaultProps` for `hasGutters`,
  `headingLevel`, `isExclusive` and `variant`.
  ([#42](https://github.com/soroush-tech/design-system/issues/42))
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Accordion/Accordion/README.md)
- **`Chip`** - a compact tag: `label` (truncated when long), `variant` (`contained` or `outlined`),
  `color`, `size`, `shape` (`square`, `rounded` or `pill`, the default) with a `borderRadius` that
  wins over it, an `icon` or an `avatar`. `onClick` makes it a button - one tab stop; `onDelete`
  shows a delete control, named by `deleteLabel`, that is a button of its own and out of the tab
  order, and deletes on Backspace and Delete on the chip too (a chip that only deletes takes the
  focus for them). A filled chip is the theme's `contrastText` on the color's `main`.

  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/design-system/src/Chip/README.md)
- **`Badge`** - a count or a dot over another element: `badgeContent`, `max` (a count past it shows
  `max+`), `variant` (`standard` or `dot`), `color`, `isHidden`, `shouldShowZero` (a count of zero
  shows no badge otherwise), `anchorOrigin` (the corner; `end` is the left right to left) and

- **`Alert`** (with `AlertTitle`) - an inline message with a `severity` (`success`, `info`,
  `warning` or `error` - picks the icon and the palette color), a `variant` (`standard` tinted,
  `contained` or `outlined`), an `icon` (`false` draws none), an `action` and, given `onClose`, a
  close control named by `closeLabel`. `role` is `alert` (announced at once) or `status`
  (politely). Tinted and outlined, its text is the theme's `text.initial`, checked against AA for

- **`Fab`** - a floating action button: the one main action of a page, `circular` (its icon) or
  `extended` (a pill with a label and a `startIcon`). It is a `Button` - its focus ring, press
  state and disabled behavior - raised on a theme shadow, as tall as an avatar of its `size`, in the
  `color` given. Where it floats is the page's: no position is built in. A circular fab is named by
  `aria-label` or `aria-labelledby`. `theme.components.Fab` styles `root`, with `defaultProps` for
  `variant`, `color` and `size`.
  ([#46](https://github.com/soroush-tech/design-system/issues/46))

- **`Snackbar`** - a transient message in a corner of the window, through a `Portal`: `isOpen` /

  `snackbar` key of `theme.zOrder`, beside the new `tooltip` one. It hides itself after
  `autoHideDuration`; the clock stops while the pointer or the focus is on it and starts again for

  controlled, the owner closes it, uncontrolled it closes itself - but not on a click away. A

### Changed

- `MenuItem`'s `value` is optional outside a `Select` (a menu row needs none).
- `Icon`'s `size` takes a theme icon size by name - `sm`, `md`, `lg` - as well as a length.
  `size="sm"` used to reach the svg as an unknown width, so the icon collapsed to nothing.

### Fixed

- **`<Select native>` keeps its accessible name.** The native path dropped `aria-label` and
  `labelId`, so a native select had no name; it now passes them to the `<select>`, as the custom
  listbox does on its trigger.

### BREAKING CHANGES

- **Responsive props switch at the window classes.** Without `theme.breakpoints`, array props
  used styled-system's defaults (40em / 52em / 64em). A theme built from `baseTheme` now has
  `xs` 0, `sm` 600, `md` 840, `lg` 1200 and `xl` 1600px: `display={['none', 'none', 'block']}`
  shows from 840px instead of 832px, and a four-value array reaches `lg`. Migrate: move each call
  site to named keys (`{ xs: 'none', lg: 'block' }`) at the class you mean.
- **`_` is no longer a responsive key** - use `xs`, the base class.
- **Generated queries are range syntax** (`@media (width >= 840px)`), through
  `@soroush.tech/styled-system`.
- **`Drawer` is an HTML popover.** It opens from a `DrawerToggle` and closes on Escape or a click
  outside without JavaScript, and its content is always in the page. It needs an `id`;
  `isOpen` becomes optional (controlled use); `onClose`'s reasons are `'escapeKey'` and
  `'dismiss'`; `shouldUsePortal`, `portalContainer`, `shouldKeepMounted` and
  `shouldEnforceFocus` are gone - the browser's top layer replaces the portal. Migrate:
  `<Drawer id="nav">` with a `<DrawerToggle drawer="nav">`, or keep `isOpen` / `onClose` and add
  an `id` - `popovertarget` names its drawer by `id`, which is what works without JavaScript. In
  a browser without the Popover API (Safari before 17, Firefox before 125) the drawer stays
  closed instead of throwing. Unit tests in jsdom, which has no Popover API, install
  `installPopover()` from the new `@soroush.tech/design-system/testing` subpath.
- **`Theme` requires `breakpoints` and `layout`.** A theme written out by hand as a full `Theme`
  object no longer typechecks. Migrate: build it with `createTheme(baseTheme, ...)`.

### Packaging

- Depends on `@soroush.tech/styled-system` `^6.0.0` (range-syntax queries, helpers, container
  queries, the layout grid).
