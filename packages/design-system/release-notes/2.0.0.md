## @soroush.tech/design-system@2.0.0

The theme now holds the page's breakpoints and layout (columns, margins, gutters, side panels and
bars), so an app lays out from the same tokens a design tool draws.
([#344](https://github.com/soroush-tech/core/issues/344))

### Added

- **`theme.breakpoints`** (`ThemeBreakpoints`) - `tablet` 37.5em, `web` 75em, `wide` 100em
  (600 / 1200 / 1600px at the browser's default font size). A value is a CSS length, a media
  condition such as `(600px <= width < 1200px)`, or a full `@media` rule. Responsive props use
  them by name, `p={{ _: 2, web: 4 }}`, or by position, `p={[2, 3, 4]}`.
- **`theme.layout`** (`ThemeLayout`) - a complete `base` entry, then one partial entry per
  breakpoint, merged mobile-first. An entry holds `bars` (`LayoutBars`: `top`/`bottom` heights,
  `0` removes a bar), `panels` (`LayoutPanels`: `start`/`end`, each a `LayoutPanel` with `mode`
  `inline` | `overlay` | `collapsed` | `hidden`, `width` and `railWidth`) and `content`
  (`LayoutContent`: `columns`, `margin`, `gutter`, `mode` `fluid` | `fixed`, `maxWidth`). Margins
  and gutters are `theme.space` keys (`LayoutSpace`); widths, heights and `maxWidth` are a space
  key or a CSS length (`LayoutLength`). `baseTheme` uses 4 / 8 / 12 / 16 columns.
  [docs](https://github.com/soroush-tech/core/blob/main/packages/design-system/docs/theming.md#breakpoints-and-layout)
- **`PageLayout`** - the page frame from `theme.layout`: `topBar`, `bottomBar`, `startPanel`,
  `endPanel` and the content container, arranged per breakpoint in CSS alone, so server
  rendering matches the client. `openPanels` opens `overlay` panels.
  [docs](https://github.com/soroush-tech/core/blob/main/packages/design-system/src/PageLayout/PageLayout/README.md)
- **`PageLayoutContext`** - each bar and panel tells its contents where they are
  (`{ region: 'bar', placement }` or `{ region: 'panel', side }`).
- **`Sidebar` in a `PageLayout` panel** fills the panel's track; where the track is narrower than
  the panel's open width (a collapsed rail), a container query shows the items' icons only.
  `expandedWidth` or `collapsedWidth` keep the rail sized by props. `SidebarItem`'s row carries a
  `data-sidebar-item-content` attribute for that rule.
- **`AppBar` in a `PageLayout` bar** takes the bar's height; a `height` prop wins. A Sidebar or
  AppBar outside a `PageLayout` is unchanged.
- **`LayoutGrid`** - a `Grid` on each breakpoint's content columns and gutter.
  [docs](https://github.com/soroush-tech/core/blob/main/packages/design-system/src/PageLayout/LayoutGrid/README.md)

### BREAKING CHANGES

- **Responsive props switch at the new breakpoints.** Without `theme.breakpoints`, array props
  used styled-system's defaults (40em / 52em / 64em). A theme built from `baseTheme` now carries
  37.5em / 75em / 100em, so `display={['none', 'none', 'block']}` shows at 1200px instead of
  832px. Migrate: move each call site to named keys (`{ _: 'none', web: 'block' }`) at the
  breakpoint you mean, or set your own `breakpoints` with `createTheme`.
- **`Theme` requires `breakpoints` and `layout`.** A theme written out by hand as a full `Theme`
  object no longer typechecks. Migrate: build it with `createTheme(baseTheme, ...)`, or add both
  keys.

### Packaging

- Depends on `@soroush.tech/styled-system` `^5.9.0` (named breakpoints for arrays, media
  conditions as breakpoint values).
