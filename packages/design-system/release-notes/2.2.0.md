## @soroush.tech/design-system@2.2.0

Works with React 18 as well as 19
([#78](https://github.com/soroush-tech/design-system/issues/78)), sets itself up in a React app
with `npx @soroush.tech/design-system init`
([#79](https://github.com/soroush-tech/design-system/issues/79)), and the AI setup guides work for
any coding agent ([#87](https://github.com/soroush-tech/design-system/issues/87)).

### Added

- **`npx @soroush.tech/design-system init` sets the design system up in a client-rendered React
  app**, whatever builds it (Vite, webpack, Rspack, Parcel, Create React App), in TypeScript or
  JavaScript. It writes `src/theme/themes` (a `light` and a `dark` theme, each a
  `createTheme(baseTheme, {...})` call you edit) and `src/theme/Providers` (`ThemeProvider` with
  the package's base page styles), wraps the tree your root renders in `<Providers>`, and installs
  the package with your own package manager. It is careful with your app:
  - It shows every change first - the files, each edit as a diff, the install - and writes
    nothing before a yes. `--dry-run` shows them and exits; with no terminal and no `--yes`, it
    only shows them.
  - It runs only in a git repository with no uncommitted change, unless `--force`.
  - It never overwrites a file. It edits the root only when the root has the standard shape -
    one `createRoot(...).render(` or `ReactDOM.render(` call - and reads each edit back;
    otherwise it prints the lines to add.
  - When a write fails, it takes back every change it made. The install runs last, with no
    scripts.
  - A second run finds its own files by their first line and changes nothing.
  - It checks your React against this package's peer range, and never upgrades React.
  - It reaches no network but the install, and writes only inside the app, through no symbolic
    link.

  It ends by pointing at the fonts guide, the house-style skill
  (`npx skills add soroush-tech/design-system`) and the MCP server's address, and writes no agent
  folder. Next.js, Vike and React Router apps are refused for now, with a pointer to the setup
  guide.

- **`createCache` from `@soroush.tech/design-system/engine`**, so an app that needs an Emotion
  cache of its own does not install `@emotion/cache` itself.
- **React 18 support.** `react` and `react-dom` peer ranges widen from `^19.0.0` to
  `^18.0.0 || ^19.0.0`. The range is measured: every unit and browser test passes on 18.0.0, 18.3.1,
  19.0.0 and 19.3.1, and CI now runs the unit tests on 18.0.0 and 19.0.0. React 17 and older are
  not supported: the components use `useId` and `useSyncExternalStore`, which React 18 added.
- **`Button` and `Pressable` take a `ref`**, typed, to their element. On React 18 a ref reaches a
  function component only through `forwardRef`, so `Button`, `Pressable`, `Fab`, `FabMenuItem`
  and `Tooltip` now use it. That is also what lets a `Menu` give focus back to a `Button` trigger,
  and a `Tooltip` place itself against a `Button`, on React 18. On React 19 nothing changes.

### Fixed

- A `Menu`, a `Tooltip` and the transitions `Fade`, `Grow`, `Slide` and `Zoom` kept the ref of the
  element they wrap only on React 19: React 18 keeps an element's ref off its props. They now read
  it where each version keeps it.

### Changed

- **`ThemeProvider`'s `children` is optional**, as a provider's is: `createElement(ThemeProvider,
  { theme }, ...children)` typechecks.
- **The README's "Use it with AI tools" section works for any coding agent.** It leads with the
  house-style skill, installed for whichever agents you use with
  `npx skills add soroush-tech/design-system`, and the hosted MCP server's address,
  `https://mcp.soroush.design/mcp`, for any MCP client. The Claude Code plugin follows as the
  one-step route for that agent.
- **A WCAG 2.2 AA skill installs beside the house-style skill.** `npx skills add
  soroush-tech/design-system` and the Claude Code plugin now also offer `wcag`: contrast under
  `opacity`, labels for `Checkbox`, `Switch` and icon-only controls, unique landmark labels, and
  how to test accessibility in an app, with or without Storybook.
- **The consumer guides no longer point at places a reader cannot open.** `docs/consumer/`
  (the setup checklist, the layout kit and the brand `theme.ts`) named private repositories and
  one internal app; they now describe the setup on its own terms. The setup checklist installs
  `^2.2.0` instead of `^1.3.1`, and its fonts section reads as a choice for your app.

### Packaging

- The package has a `bin`, `design-system`: `dist/bin.mjs`, one ESM file that imports only
  Node's own modules. The browser entries are unchanged.
- Dev-dependency bumps: the Storybook packages (`storybook`, `@storybook/addon-a11y`,
  `@storybook/addon-docs`, `@storybook/addon-vitest`, `@storybook/react-vite`) `^10.6.3` ->
  `^10.6.7`, `@types/node` `^26.6.5` -> `^26.6.6`, `@vitest/browser-playwright`,
  `@vitest/coverage-v8` and `vitest` `^5.0.5` -> `^5.1.0`, `oxlint` `^1.89.0` -> `^1.93.0`,
  `playwright` `^1.64.1` -> `^1.65.0`, `tsdown` `^0.22.14` -> `^0.23.7`.
- `jsdom` `^29.1.1` -> `^31.0.0` for the unit tests. jsdom now computes styles as a browser
  does (lengths in px, transitions in seconds, media queries applied), and the tests expect those
  values.
