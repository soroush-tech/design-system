## @soroush.design/react-theme@0.1.0

The theme of the soroush.design React platform, in a package of its own
([#130](https://github.com/soroush-tech/design-system/issues/130),
[#131](https://github.com/soroush-tech/design-system/issues/131)). The component library is built on
it, and an app can use it with none of our components: it builds its own components on the same
tokens and gets the same server-rendered styles.

### What it offers

- **`ThemeProvider` and the hooks that read the theme.** `ThemeProvider` provides one theme and
  merges the optional `defaults`. `useTheme` returns it, `useDefaultProps` reads a component's
  `theme.components[name].defaultProps`, `withTheme` hands it to a class component, and
  `LayoutProvider` changes the layout tokens for a part of the page.
  [docs](https://github.com/soroush-tech/design-system/blob/main/packages/react-theme/README.md)
- **The configured styling API.** `styled`, `css` and `keyframes`, typed against the theme, with the
  prefix `soroush`, value repair and the raw theme keys already set. `styled(tag, { name, slot })`
  makes a component customizable through `theme.components`. `Global`, `globalStyles` (the base
  reset), `CacheProvider`, `styleCache` and `createCache` are for apps that render their own global
  styles or extract critical CSS, and `useStyle`, `withStyles` and `StylesConsumer` are the custom
  CSS layer.
- **The theme's types.** The core's token scales, `baseTheme` and `createTheme` are re-exported
  unchanged, with the `Theme` type that adds `theme.components`. Every scale is an open interface:
  an app adds to it with `declare module '@soroush.design/react-theme'`, or with the name of the
  umbrella, the component library or the core.
- **An open `ThemeComponents`.** `theme.components` is typed by an interface that starts empty. A
  component library adds its components to it with a `declare module` block in its own declarations,
  and an app adds its own, with `ComponentConfig`, `ComponentStyle` and `ComponentVariant` as the
  building blocks.
- **Configured by a function.** The engine is set up by a function the package's own `styled` calls
  before its first use, not by a module imported for its effect, so an app that imports only
  `styled` gets the configuration.
- **Server rendering.** The outermost `ThemeProvider` declares the theme as CSS variables on
  `:root`; server output carries the base styles first, then the classes. Under a style policy that
  allows style elements by nonce, the engine's style element carries the nonce of the page's
  scripts.
- **Four entry points.** `@soroush.design/react-theme` holds everything, and `/theme`, `/style` and
  `/engine` hold the same names by area. An app that installs the React umbrella writes
  `@soroush.design/react/theme`, `@soroush.design/react/style` and
  `@soroush.design/react/engine`.

### Packaging

- Peers: `react` and `react-dom` `^19.2.8`.
- Dependencies: `@soroush.design/core` and the UmberStyle engine (`@umber-style/cache`,
  `@umber-style/react` and `@umber-style/styled`, `^0.3.0`).
- ESM and CJS builds with declarations, and a subpath export for each of the four entry points.
- The package exists once in an app: `@soroush.design/react-components` and
  `@soroush.design/react` depend on it and never bundle it, because two copies would be two React
  contexts and two engine configurations.
